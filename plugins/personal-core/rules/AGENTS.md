# 全局协作规范与知识治理

本规则随 `personal-core` 插件常驻，仅约束跨项目通用协作、工程纪律、中文文案与知识分流；项目技术栈、命令与边界以仓根 `AGENTS.md` 为准。

## 1. 身份、语言与沟通方式

- **始终使用简体中文回复**。
- **个人背景边界（本地按需补充）**：可仅在本地写明地区、业务与默认前提，避免误套用假设；**严禁将密钥、个人隐私或敏感业务规则提交至公开仓库**。
- **少追问、带假设推进**：可查证或常识可定的事项直接推进，仅三类场景停下请用户拍板：
  1. 决策偏差会造成明显返工；
  2. 需求超出当前范围，涉及跨仓改动或架构升级（须先列 scope delta）；
  3. 线上高风险或不可逆变更（生产发布、新建线上云资源、删库或远程库迁移）。

## 2. 工程与交付纪律

- **轻量 SDD**：跨多文件改动先对齐计划或 `specs/`，确认后端到端推进至验证；单文件小改直接完成；长文档先搭骨架再填细节。
- **先核后改、失败查根因**：改前核对仓内 canonical 先例，改 UI 前确认处于生效渲染路径；构建或测试失败严禁以「非本方案引起」敷衍，须查明真实根因。
- **编码与换行保护**：编辑已有文件保留原换行（LF / CRLF）与编码（勿剥离 UTF-8 BOM）。
- **工具单一职责**：VCS 与 GitHub 用 `git` / `gh` CLI；实时页面核验用内置 `browser` subagent，回归跑项目 E2E 脚本；仅当存在 `.codegraph/` 且启用 `codegraph` MCP 时，用 `codegraph_explore` 查符号与调用链。

## 3. 通用文案规范（写给人看的字）

1. **改前先指错**：修改已有界面或文档文案前，先指出具体毛病（规则错、漏信息、拗口、过期），说不出问题不随意重写。
2. **用词统一**：术语与交互名称向界面及行业惯例靠拢，不自造生词。
3. **杜绝翻译腔**：表意自然准确，禁用「它」代指人、硬凑主语或直译英文词条。
4. **事实对齐代码**：数量限制、校验规则与实际行为须核对代码常量与实现，禁止凭记忆估算。

## 4. 四层知识分流与沉淀三门禁

### 四层知识分流

| 知识类型 | 存放位置 | 读取与维护准则 |
| --- | --- | --- |
| 代码结构、符号与调用链 | 实时源码 / `codegraph_explore` | 现查现用，禁写进规则背诵 |
| 仓库命令、边界与不变量 | 仓根 `AGENTS.md`（≤ 20 KB）与 `.agents/rules/<topic>.md` | 规则**累加合并**非覆盖，全局勿写冲突技术栈；按文件/场景用 `trigger: glob` / `model_decision` |
| 多步骤可重复工作流 | `.agents/skills/<name>/SKILL.md` 或全局 Skills | 渐进披露按需加载，不占常驻上下文 |
| 隐蔽口径、环境坑点与纠偏 | `/learn`（生成 scoped Rule/Skill）或项目已配置记忆目录 | 仅沉淀高价值结论，遵守三门禁 |

### 沉淀三门禁

1. **三不写**：不写源码可查的实现细节与行号；不写一次性单号、瞬时开关状态或待办；**严禁写入明文密码、API Key、Token 或私钥**。
2. **先查后写、合并优先**：写入持久化规则、Skill 或记忆前先检索同类条目；有则原地合并纠偏，无匹配再按目标格式精简新建（只记结论、原因与入口符号）。
3. **显式报备**：每次新增或更新持久化知识后，在回复末尾用一行说明改动路径与核心结论。
